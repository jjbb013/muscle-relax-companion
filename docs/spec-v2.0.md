## 1. 产品定位与核心痛点

### 1.1 定位

一款 i 人友好、零沟通压力、纯本地隐私的身体酸痛记录、按摩放松需求可视化、自助舒缓参考工具。

两大核心能力：

1. **对外沟通**：替用户向按摩师可视化 + 文字 + 语音播报精准表达"哪里不舒服、希望怎么按"，解决用户难以口头描述酸痛位置、肌肉区域的痛点，同时适配视障 / 听障从业者。
2. **对内自助**：基于本地人体肌肉 / 常用按压点数据库，为用户提供对应部位的日常舒缓动作、拉伸参考（非医疗指导）。

### 1.2 核心红线（硬性）

1. **零服务端、零数据上传**：所有用户记录、输入永不联网、永不上传。
2. **零外部 AI 调用**：语音转写、语义识别、语音播报仅使用 iOS 系统框架。
3. **非医疗属性（全文一致口径）**：禁止出现"治疗、诊疗、诊断、治病、疗效、康复、理疗、处方"等词汇；所有功能表述为"记录、沟通、放松参考"。
4. **极致轻量化**：模型、数据库、用户数据最小体积化。
5. **全隐私可控**：备份、导出、恢复完全由用户手动触发，无自动同步。

### 1.3 目标用户

1. 不擅长口头表达身体酸痛位置的普通用户
2. 长期久坐、肩颈腰背高频疲劳人群
3. 需要与按摩师精准沟通放松需求的人群
4. 需要留存身体状态记录、定期复盘的用户

### 1.4 市场区域

主打中国大陆市场（需完成 APP 备案，见 §15），多语言为辅助适配。

## 2. 整体架构（纯本地离线）

- 无后端服务器、无云端数据库、无任何数据上报 SDK
- 所有计算、识别、渲染、存储全部在设备本地完成
- 隐私政策文本托管于免费静态页面（如 GitHub Pages），**仅承载政策文本，不收集、不记录任何访问数据**；应用本体仍零服务端

## 3. 技术选型（v2.0 修订定稿）

| 项目 | 选型 | 说明 |
| --- | --- | --- |
| 开发语言 | Swift（最新稳定版） | SwiftUI 为主，SceneKit 场景经 UIViewRepresentable 桥接 |
| 本地数据库 | Core Data + 字段级 AES-256 加密 | 见 §3.1 加密策略 |
| 密钥托管 | Keychain（kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly） | 不解锁不读、不跨设备迁移 |
| 数据保护 | 文件级 NSFileProtectionComplete | 锁屏后文件不可读 |
| 3D / 2D 人体可视化 | SceneKit（首选）/ SwiftUI 2D 人体热区图（降级方案） | 见 §3.3 资产策略 |
| 语音转写 | Speech 框架（SFSpeechRecognizer） | **仅设备级 on-device 识别，不支持则降级为文字输入**（见 §3.2） |
| 语义识别 | NaturalLanguage（NLTagger 分词）+ 本地部位词典 + 同义词表匹配 | 无云端 NER，词库随包内置 |
| 语音播报 | AVSpeechSynthesizer 系统音色 | 中/英/日系统合成语音，效果以系统实际为准 |
| 数据压缩 | Apple Compression 框架内置 LZ4（COMPRESSION_LZ4RAW） | **系统原生，不引入任何第三方压缩库** |
| 备份方案 | 手动导出 / 导入 LZ4 压缩 JSON | 通过系统文件选择器由用户显式选择位置 |
| 第三方依赖 | 无（开源组件亦为零） | 上架隐私标签可声明"不收集任何数据" |

### 3.1 Core Data 加密策略（v2.0 新增，定稿）

- **明文存储（保证可检索、可排序）**：记录 ID、创建时间、部位区域 ID、酸痛等级、模板 ID
- **AES-256 加密存储（写入前加密）**：用户自由文本（症状描述、自定义需求文案）、自定义模板内容
- 加密密钥仅存于 Keychain，不落盘、不进备份元数据
- **代价声明**：加密字段不参与全文搜索，历史记录仅支持按时间 / 部位 / 等级筛选
- 不使用 SQLCipher 等第三方加密库

### 3.2 语音识别能力边界（v2.0 关键修订）

**不做"离线转写"承诺，改为分级策略：**

1. 运行时检测 `SFSpeechRecognizer.supportsOnDeviceRecognition`（iOS 13+，部分语言/设备支持，iOS 16 覆盖率显著提升，故最低版本定为 iOS 16）。
2. **支持时**：语音在设备本地完成转写，全程不联网。
3. **不支持时（含日语离线包未下载、旧设备等）**：界面明确提示"当前设备暂不支持本地语音输入，请使用文字描述"。文字输入路径功能完整，与语音路径等价。
4. 文案规范：对外统一表述为「语音输入（支持设备上本地完成）」，**禁止**宣传"离线中/英/日语音转写"。

### 3.3 3D 资产策略与降级方案（v2.0 新增）

1. **资产来源**：选用带肌肉分区标注的可商用授权低模人体模型（开发前完成授权条款确认，记录于仓库 LICENSE 文件）；自建模型不在排期内。
2. **资产要求**：三角面数 ≤ 10 万、贴图 ≤ 2048px、单模型文件 ≤ 15MB。
3. **降级方案（允许首发启用）**：若授权/成本不可行，改用 SwiftUI 绘制「正面 + 背面 2D 人体示意图 + 可点击热区」，功能（部位选择、数据匹配、文案生成）与 3D 完全一致，仅视觉降级。2D 热区图需覆盖全部高频部位（见 §6.1）。
4. 穴位信息以**数据点位**形式叠加显示（标注点 + 名称），不依赖模型精细度。

## 4. 数据模型（v2.0 新增，定稿）

```javascript
BodyRegion（部位，内置静态数据）
├─ id: String            // 如 "shoulder_l"
├─ displayName: String   // 多语言键值
├─ side: enum { left, right, center }
├─ category: enum { neck, shoulder, back, waist, abdomen, upper_arm,
│                    forearm, hip, thigh, calf, knee, other }
├─ muscleNames: [String]        // 关联肌肉名称（展示用）
├─ pressPoints: [PressPoint]    // 常用按压点（见下）
└─ isFineRendered: Bool         // 是否精细渲染区（高频区=true）

PressPoint（常用按压点，内置静态数据，非医疗表述）
├─ id: String
├─ name: String          // 通用名称，如"肩井区域"（文案加"参考"后缀）
├─ regionId: String
└─ note: String          // "位置示意，仅供参考"

SoreRecord（酸痛记录，用户数据，加密字段标注 🔒）
├─ id: UUID
├─ createdAt: Date
├─ regionId: String
├─ side: enum { left, right, center, both }
├─ level: Int            // 1 轻微软胀 / 2 中度酸胀 / 3 重度紧绷
├─ symptomText 🔒         // 用户自由描述（加密）
├─ generatedText 🔒       // 生成的标准化沟通文案（加密）
├─ source: enum { manual, voice, template }   // 记录来源
└─ templateId: String?   // 若由模板生成

UserTemplate（自定义模板，用户数据）
├─ id: UUID
├─ name 🔒
├─ content 🔒
├─ regionId: String
└─ updatedAt: Date

AppSettings（设置，用户数据）
├─ language: enum { zh, en, ja }        // 播报语言
├─ backupReminderEnabled: Bool          // 定期备份提醒（本地通知）
├─ disclaimerAcceptedVersion: String    // 已同意的免责声明版本号
└─ onboardingCompleted: Bool
```

静态数据（BodyRegion / PressPoint / 内置模板）随包内置，只读，不进用户备份。

## 5. 备份与恢复（v2.0 定稿）

### 5.1 规则

1. 用户数据（SoreRecord / UserTemplate / AppSettings）可导出为 **LZ4 压缩的标准 JSON** 文件。
2. 导出/导入通过 `UIDocumentPickerViewController` 由用户显式选择位置，可选：本机"文件"App 任意目录 / 用户自选的 iCloud Drive 目录。**应用本身不持有任何同步逻辑，不自动备份、不自动同步**。
3. 备份提醒：设置页开关，开启后经**本地通知**每周提示一次，通知内容不含任何健康数据。
4. 卸载重装后，用户可手动导入备份恢复全部数据。

### 5.2 备份文件 Schema（v2.0 新增）

```json
{
  "schema_version": 1,
  "app_version": "1.0.0",
  "exported_at": "2026-09-08T20:30:00+08:00",
  "records": [
    {
      "id": "uuid",
      "created_at": "ISO8601",
      "region_id": "shoulder_l",
      "side": "left",
      "level": 2,
      "symptom_text": "（AES-256 密文，Base64）",
      "generated_text": "（密文）",
      "source": "manual",
      "template_id": null
    }
  ],
  "templates": [ ...同上结构... ],
  "settings": { ... }
}
```

- 敏感字段在导出前仍处于加密状态（密文直接打包），备份文件本身再加一层 LZ4 压缩。
- `schema_version` 必填，未来结构升级必须提供迁移函数；导入时版本高于当前 App 支持的版本则拒绝并提示升级 App。

## 6. 功能需求

### 6.1 人体可视化交互

1. 精细渲染区（3D 高模或 2D 放大热区）：颈、肩、背、腰、腹、大腿、小腿、膝。
2. 基础点位区：上臂、前臂、髋、足等，仅提供点位选择与基础说明，不做精细渲染。
3. 交互：单指旋转/平移、双指缩放（3D）；点击选中区域后高亮反馈（轻微放大 + 渐变填色 + 柔和回弹），并展示该区域关联信息：肌肉名称、常用按压点列表（标注"仅供参考"）、常见疲劳场景说明、适配的放松方式建议。
4. 左右侧处理：所有双侧部位独立可选（shoulder_l / shoulder_r），选中时模型视角自动微倾至该侧。

### 6.2 部位识别冲突处理（定稿）

1. 当语音/文本识别部位与用户手动点击部位不一致时，强制弹出确认弹窗，并列展示两个候选位置（名称 + 示意图高亮）。
2. 必须用户手动确认最终部位后才生成沟通文案与播报，杜绝左右侧识别错误。

### 6.3 语音与文本语义识别

1. 语音输入遵循 §3.2 分级策略；默认语言跟随 App 语言设置。
2. 语义识别实现：NLTagger 分词 → 本地部位词典（含同义词表："脖子/脖颈→颈部"、"腰眼→腰"等）匹配 → 输出 `regionId` + `side` + 等级推断词（可选）。
3. 识别失败或不置信时：不强行匹配，界面引导用户手动点选部位（识别是辅助，手动选择永远是完整可用的兜底路径）。

### 6.4 语音播报（双通道无障碍沟通）

**场景逻辑（v2.0 修订）**：用户把手机递给按摩师时——

- 视障从业者：依赖**语音播报**接收需求
- 听障从业者：依赖**屏幕超大号加粗静态文字**
两者互为兜底，均需完整支持。

功能规则：

1. AVSpeechSynthesizer 系统合成语音，支持中/英/日切换，音色以系统设置为准（不承诺"真人音色"，文案统一写"系统高质量语音"）。
2. 播报时屏幕同步展示超大号（≥ 34pt 加粗）静态文字，文字与语音逐段同步高亮。
3. 支持暂停 / 继续 / 重播 / 系统音量调节。
4. 如用户已下载系统"增强语音"音色包则自动使用（一次性用户主动行为，非应用联网）。

### 6.5 高频放松模板

1. 内置模板（随包静态资源，约 8-12 个）：久坐肩颈紧绷、伏案背部发紧、腰部疲劳、小腿酸胀、运动后肌肉紧绷、长途驾车腰背僵硬等。
2. 模板内容为**通用身体放松常识**整理，来源为公开的运动健康通识，不含医疗指导；每条模板附"非医疗属性"轻提示。
3. 支持用户自定义模板（本地加密保存）、一键套用生成沟通文案。

### 6.6 自助舒缓参考

1. 按选中部位调取内置图文教程：拉伸动作、放松姿势、日常缓解建议（静态内容随包内置）。
2. **不含外部视频/网页链接**（v2.0 修订：去除外链，规避内容失控与审核风险）。

### 6.7 历史记录与复盘（v2.0 新增，补全 1.3 第 4 类用户需求）

1. 记录列表页：按时间倒序展示历史记录（部位、等级色标、时间、来源）。
2. 记录详情页：完整文案 + 可重新播报 + 可编辑/删除。
3. 复盘视图：近 30 天部位分布统计（简单条形/色块图）、等级趋势，数据全部本地计算。
4. 支持单条删除与清空全部数据（二次确认）。

2. **记录流程（分步）**：① 选择部位（可视区点选）→ ② 描述症状（语音/文字/模板套用）→ ③ 生成沟通文案（可编辑）→ ④ 播报展示（大字 + 语音）。每步仅展示必要内容，可返回修改；步骤间状态保留。

### 7.4 动效

点击部位：放大 1.05× + 渐变填色 + 柔和回弹（≤ 300ms）；卡片选中：上浮 2pt + 阴影增强；弹窗：淡入淡出 + 低饱和遮罩；播报文字逐段高亮；全程 60fps，无重型动画。

## 8. 合规规范

### 8.1 文案红线（全文一致执行）

- 禁用词：治疗、诊疗、诊断、治病、疗效、康复、理疗、处方、治愈、 medical claims
- 统一口径：**「本应用仅为身体状态记录、按摩放松沟通与日常舒缓参考工具，不具备医疗功能，不能替代专业医疗建议；身体不适请及时前往正规医疗机构就诊。」**
- 按压点表述：统一为"常用按压点（位置示意，仅供参考）"

### 8.2 强制交互

1. 首次启动：免责声明需滚动至底部方可点击"同意并进入"，记录已同意版本号；条款更新后需重新确认。
2. 每次生成沟通文案时，页面固定位置轻提示非医疗属性（不弹窗打断）。

### 8.3 隐私政策

1. 隐私政策以静态页面托管（如 GitHub Pages），页面不收集任何数据；App 内与 App Store 审核均提供该 URL。
2. 政策明确公示：所有数据仅本地加密存储；无第三方 SDK、无数据采集、无追踪；备份完全由用户手动掌控。
3. App Store 隐私标签声明：不收集任何数据。

### 8.4 权限清单（v2.0 修订，含通知）

| 权限 | 用途 | 时机 |
| --- | --- | --- |
| 麦克风 | 语音输入（仅设备本地识别） | 用户首次点击语音按钮时申请 |
| 本地通知 | 备份提醒 | 用户开启备份提醒开关时申请 |
| 文件访问 | 备份导入/导出 | 通过系统文件选择器，零敏感权限 |

不申请：定位、相册、通讯录、健康（HealthKit）等一切无关权限。

## 9. 错误处理与降级方案（v2.0 新增）

| 场景 | 处理 |
| --- | --- |
| 设备不支持本地语音识别 | 提示并降级为文字输入（功能完整） |
| 语音识别超时/无结果 | 保留录音重试入口，可改文字输入 |
| 语义识别无匹配 | 不强行匹配，引导手动点选部位 |
| 3D 模型加载失败 | 自动降级 2D 热区图；2D 亦失败则纯列表选择 |
| 语音播报失败（无声/无音色） | 大字展示完整保留，提示检查系统音量/静音开关 |
| 备份文件损坏/版本过高 | 明确报错，不写入任何数据；支持重新选择文件 |
| 导入与现有数据 ID 冲突 | 以导入数据为新副本生成新 ID，不覆盖现有数据 |
| Keychain 读取失败（如恢复备份后） | 重建密钥并提示"加密记录需原设备重新导出"（明文字段不受影响） |

## 12. 开发排期（v2.0 修订，单人开发估算）

> 总周期约 4-6 个月。每个阶段产出可独立验收；阶段 2.5 可与阶段三并行。

- **阶段 0（前置，1-2 周）**：3D 模型资产选型与商用授权确认（不可行则确认启用 2D 降级方案）；APP 备案材料准备与提交。
- **阶段一：隐私底座与数据体系（3-4 周）**：Core Data + 字段加密 + Keychain；备份导出/导入（含 Schema 与版本迁移）；免责声明与隐私政策页面；权限申请框架。**验收：数据加密字段落盘不可读；导出→删除→导入后数据 100% 一致；断网全功能可用。**
- **阶段二：核心可视化 + UI（6-8 周）**：设计 Token 与全局组件；首页/流程页/历史页/设置页；3D（或 2D）人体可视化与部位点选、区域信息展示。**验收：7.2 全部高频部位可点选且信息正确；帧率与包体达标；3D 失败可自动降级。**
- **阶段三：语音与语义（4-5 周）**：本地语音输入分级策略；部位词典与同义词匹配；冲突二次确认；中/英/日播报 + 大字同步展示。**验收：不支持 on-device 的设备正确降级；冲突弹窗逻辑覆盖左右侧用例；播报与文字逐段同步。**
- **阶段四：模板、复盘与打磨（3-4 周）**：内置模板、自定义模板；历史复盘视图；VoiceOver 适配；全部合规文案定稿；性能与包体优化；测试与修复。
- **阶段五：上架（2-4 周，与备案进度耦合）**：备案号获取 → 隐私标签 → 截图与元数据 → 提交审核 → 驳回修正。

**MVP 裁剪建议（可选）**：若希望最快上架验证，可首发 = 阶段一 + 阶段二（2D 方案）+ 文案生成与播报（不含语音输入），将阶段三的语音识别后置为 1.1 版本更新。

## 13. 交付总结

1. 100% 纯本地离线运行，隐私政策可如实声明"不收集任何数据"。
2. 解决"不会表达酸痛位置、难以与按摩师沟通"的核心痛点。
3. 视障（语音）/ 听障（大字）双通道兜底，VoiceOver 全适配。
4. 数据本地加密、可手动备份永久留存。
5. 极简健康类 UI，合规文案全程非医疗口径。
6. 个人开发者免费合规上架（完成 APP 备案前提下）。
7. 可持续迭代：更多部位、模板、教程均为本地静态资源更新，架构预留扩展空间。
